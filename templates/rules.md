# 공통 개발 규칙

- 지정된 이슈의 worktree만 고칩니다. 다른 작업 파일을 덮어쓰거나 정리하지 않습니다.
- 사람에게 질문하지 않습니다. 선택이 필요하면 브리프와 이슈의 완료 조건 안에 드는 선택을 하고, 보고서의 "결정" 제목 아래 선택과 이유를 기록한 뒤 계속 진행합니다. 모든 선택이 브리프 밖의 새 권한·외부 효과·데이터 삭제를 요구할 때만 해당 작업을 멈추고 `dv kick blocked <ISSUE> "<한 줄 이유>"`를 보냅니다. 나머지 가능한 작업은 계속합니다.
- 실패하는 시험부터 만들고 수정 전 실패 로그를 보고서에 남깁니다. 바뀐 범위에 필요한 시험만 돌립니다.
- 개발 중 리뷰 루프·설계 비평·크로스체크·CRW/relay를 실행하지 않습니다.
- base 브랜치 직접 push, force push, 원격 브랜치 삭제는 금지합니다.
- 커밋 메시지는 `<ISSUE>: ...` 형식입니다.
- `$DV_STATE/<ISSUE>/report.md`에 바꾼 것, 시험 명령·결과, red/green, 남은 것을 기록합니다.
- GitHub 저장소면 커밋 후 `dv pr <ISSUE>`까지 실행합니다. 마지막에 `dv done <ISSUE>`를 실행합니다.
- 로컬 저장소의 리뷰와 병합은 시온이 진행합니다. 리뷰 지적 수정은 시온의 `dv send` 지시를 받아 P0·P1만 한 번 처리하며 재리뷰하지 않습니다.
